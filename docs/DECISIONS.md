## v1 — React, не Flutter
Flutter не переписывать, пока флоу не живой.

## Сканер — демо и живой Gmail
Ключ Google (Client ID) уже есть: локально в `.env` (файл не в git) и должен быть на хостинге. Если ключ подхвачен, на старте главная кнопка — «Подключить Gmail», демо — второй строкой.

Живой вход читает настоящий ящик (только чтение). Демо по-прежнему открывает выдуманные письма из `src/fixtures/mailbox.ts`. Оба пути дают один и тот же список для движка.

Пока Google не проверил доступ к почте (restricted scope), войти могут только люди из списка Test users в Google Cloud. Аккаунт разработчика проходит. Чужой аккаунт Google сам отклоняет — это не поломка кнопки.

Публичный сканер для любого пользователя в Play — после этой проверки Google. Без неё кнопку «Подключить Gmail» обычный человек нажмёт и получит отказ.

## Почта — Gmail readonly
Scope `gmail.readonly` до кнопки «Отправить». SMS в v1 нет.

## Движок отдельно от UI
`src/engine/*` потом уедет в Cloud Functions. Типы — `src/types.ts`.

## Отмена
Play / Apple / PayPal → их страница подписок (инструкция), не фейковое «отправь письмо».
Web / Stripe → ссылка из письма, иначе известный URL, иначе сайт отправителя.

## Биллинг
3 бесплатные отмены → paywall: **$2.99/мес или $19.99/год** (год выбран по умолчанию, бейдж −44% против 12× месяца). Дальше Pro без лимита. В UI пока mock: любая кнопка тарифа делает `setPlan("pro")` без оплаты; `plan` / `killsUsed` в `useState`, после перезагрузки сбрасываются. Тип тарифа — `ProSku` в `src/types.ts`.

Дальше — один PWA, два кассира, один entitlement.

- Один клиент (`subkill.app`). Play APK — TWA, не отдельное приложение.
- В TWA (иконка Play): только Google Play Billing через Digital Goods API + Payment Request API (`https://play.google.com/billing`). В PWABuilder/Bubblewrap включить `playBilling`. Каталог Pro — в Play Console. Покупку подтверждать на бэкенде (Play Developer API), иначе Google вернёт деньги через 3 дня.
- В браузере (сайт, не APK): веб-эквайринг (Stripe / Paddle / аналог). Политика Play сюда не действует.
- Из APK нельзя вести на Stripe и нельзя показывать веб-кассу. Детект: `getDigitalGoodsService` есть только в TWA.
- Оба кассира пишут одно: `users.plan = pro`. Источник правды — `User` в `src/types.ts` / `schema/postgres.sql` (`plan`, `cancellations_used`, `free_cancel_limit`), не React-стейт. Ключ аккаунта — email (Gmail OAuth).
- **В демо не продавать.** После 3 отмен в учебном ящике — не касса, а лист «демо на этом»: Подключить Gmail / На старт / Остаться смотреть список без новых отмен. Выход из демо всегда: аватар и плашка «демо-ящик». Живой Gmail по-прежнему видит paywall с двумя тарифами.
- Alternative billing / external offers Play (§8/§9) не брать: Digital Goods API их не умеет, без нативной оболочки нереально.
- Нативный SDK RevenueCat в TWA не работает. RevenueCat (или свой Postgres) можно позже как шину entitlements, не как кассир в APK.

## Узкое место продукта
Верификация Google на restricted scope. Без неё в Play нет настоящего сканера.

## TWA / адресная строка в Play APK
Полоска Chrome — это Custom Tab: Digital Asset Links не совпали с подписью APK на телефоне. CSS её не убирает.

- Оба хоста `subkill.app` и `www.subkill.app` отдают `/.well-known/assetlinks.json` с 200, без редиректа. Apex→www редирект не возвращать.
- В `assetlinks.json` нужны **все** SHA-256 ключа подписи Play (quantum-ready: классический для Android 16−, новый классический и PQC для 17+) **и** ключ загрузки (upload), если ставят APK из zip PWABuilder.
- Готовый JSON копировать со страницы Play App Signing, не две строки «классический / постквантовый». Именно фрагмент Play (`61:0C:1B:4C:…`) убрал полоску; классический и PQC оставить рядом.
- Service worker не перехватывает `/.well-known/`.
- Письмо Search Console «страница с переадресацией» — про индекс поиска (часто http→https), не про TWA. Из‑за него редирект apex→www не возвращать.

## TWA / «Actief in Chrome»
Плашка снизу — обязательное уведомление Chrome, что приложение открыто в браузере. Из кода и PWABuilder её не убрать. После переустановки может всплывать несколько запусков подряд; это не баг и не адресная строка. Не пытаться прятать.
